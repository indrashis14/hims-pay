# HIMS Fee Payment Portal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A free, public fee-payment POC for HIMS. It is a static site on GitHub Pages, backed by a free Supabase project, with a simulated UPI payment flow, late fines, an admin area, and a passing 1,000-user load test.

**Architecture:** All business rules run in Postgres as `SECURITY DEFINER` RPCs, with row-level security (RLS) on every table. The browser holds only the public anon key. The frontend is plain HTML, CSS and ES modules using `supabase-js` from a pinned CDN URL, with no build step. Development and testing run against the local Supabase stack in Docker.

**Tech Stack:**
- Supabase CLI 2.120.0, Postgres 17, pgTAP
- `@supabase/supabase-js` 2.117.3
- Node 24 (`node:test`, built-in `fetch`)
- GitHub Actions + Pages

**Spec:** `docs/design.md` (revision 2, approved 2026-10-27)

## Global Constraints

- Everything stays free. No paid plan, card, or paid API anywhere.
- Fines are calculated in IST (`Asia/Kolkata`) from the **database clock**, never the client's. The rules:
  - 0 days late: ₹0
  - 1–10 days late: ₹5 × d
  - 11–20 days late: ₹50 + ₹10 × (d − 10)
  - 21+ days late: blocked unless unblocked; an unblocked student pays ₹150
- An order fixes its amount at creation and expires 10 minutes later.
- At most one `success` order and one `pending` order per (student, term), enforced by unique indexes.
- Every payment screen and bill shows "DEMO — no real money is charged".
- Login is by email + password. Phone is collected: exactly 10 digits, starting 6–9, after normalisation.
- Reset-code reply is always "If an account exists, a code has been sent to its email." OTP expiry is 600 s.
- Secrets that must never be committed: the Supabase service-role key, SMTP passwords. The anon key and URL are public by design.
- Every table and function gets explicit `grant`/`revoke` statements (Supabase's change of 2026-10-30).
- Pin every CDN script to an exact version.
- Separate browser sessions for students and admins: `storageKey` `hims-student` vs `hims-admin`.
- Production auth rate limits in `config.toml`:
  - sign-in/sign-up: 300 per 5 min per IP
  - token refresh: 1,000 per 5 min per IP
  - email sent: 100 per hour
- Load-test runs raise these limits temporarily.

## Review Focus

1. **Two tabs paying the same term at once.** Both create an order and both approve. Exactly one succeeds; the other gets `ALREADY_PAID` or returns the same bill. (Task 4: `test_two_tabs_one_payment`)
2. **Order created on day 20, approved after the block starts.** Payment succeeds at the fixed ₹150-fine amount. (Task 4: `test_order_survives_block_boundary`)
3. **Admin edits the active term's amount while a student has a pending order.** The bill shows the old, fixed amount. (Task 5: `test_term_edit_keeps_pending_amount`)
4. **Phone typed as `+91 98765 43210`, `098765 43210` or `98765-43210`.** The client normalises it to `9876543210`. The server rejects anything that is not 10 digits starting 6–9. (Task 3: `normalizePhone` tests and `test_signup_rejects_bad_phone`)
5. **A student owes an old unpaid term and the current one.** The dashboard lists both, each with its own fine and block state, and paying the old one leaves the new one unpaid. (Task 4: `test_arrears_listed_and_paid_separately`)

## Shared SQL interfaces (defined in Tasks 2–6, used by Tasks 7–9)

| RPC (schema `public`) | Grant | Returns / errors |
|---|---|---|
| `whoami()` | authenticated | `jsonb {role: 'admin'\|'student'\|'none', student: {...}?}` |
| `my_dues()` | authenticated | rows: `term_id, term_name, due_date, base_inr, days_late, fine_inr, total_inr, blocked, paid, order_id, bill_no` |
| `create_order(p_term_id bigint)` | authenticated | `order_id uuid, pay_token text, base_inr, fine_inr, days_late, total_inr, expires_at`. Errors: `NOT_A_STUDENT`, `TERM_NOT_OWED`, `ALREADY_PAID`, `BLOCKED` |
| `mock_upi_pay(p_order_id uuid, p_pay_token text, p_vpa text, p_approve boolean)` | anon, authenticated | `status text, utr text, bill_no text`. Errors: `BAD_TOKEN`, `EXPIRED`, `BAD_VPA` |
| `order_status(p_order_id uuid)` | authenticated (own order) | `text` |
| `get_bill(p_order_id uuid)` | authenticated (own order or admin) | `jsonb` with all bill fields |
| `admin_terms()`, `admin_save_term(p_id bigint, p_name text, p_amount_inr int, p_due_date date)`, `admin_stats(p_term_id bigint)`, `admin_students(p_term_id, p_filter text, p_search text, p_limit int, p_offset int)`, `admin_payments(p_term_id, p_include_failed boolean, p_limit int, p_offset int)`, `admin_unblock(p_student_id uuid, p_term_id bigint)`, `admin_outbox()` | authenticated, raise `FORBIDDEN` unless admin | see Task 5 |

Error codes are raised as `raise exception 'CODE' using errcode = 'P0001'`. The client maps `error.message` to friendly text.

### Task 4: Orders and simulated UPI

**Files:**
- Create: `supabase/migrations/20261027000004_orders.sql`
- Test: `tests/orders.test.mjs`

**Interfaces:**
- `create_order`, `mock_upi_pay`, `order_status`, `get_bill` per the table above.
- `private.finalize_payment(p_order_id uuid, p_success boolean, p_reason text, p_vpa text) returns public.orders`:
  - locks the row; if already terminal, returns it unchanged
  - on success sets `utr` (12 random digits), `bill_no` (`'HIMS-' || yyyy || '-' || lpad(nextval('private.bill_seq'),6,'0')`) and `paid_at`
- The pay token is 32 random bytes, hex-encoded. Only its sha256 is stored.
- `create_order` steps:
  1. Mark this student+term's stale pending orders as `expired`.
  2. If a still-valid pending order exists, rotate its token and return it with its original amount.
  3. Otherwise quote the fine through `fine_quote` (unblocked comes from `term_unblocks`) and insert.
- `mock_upi_pay` fails the order when `p_approve` is false or the VPA ends in `@fail` (case-insensitive).

### Task 5: Admin RPCs

**Files:**
- Create: `supabase/migrations/20261027000005_admin.sql`, `scripts/create-admin.mjs`
- Test: `tests/admin.test.mjs`

**Interfaces:**
- `private.is_admin() returns boolean`.
- Every `admin_*` RPC raises `FORBIDDEN` unless the caller is an admin.
- Per-student status for a term is one of:
  - `paid`: success order with fine 0
  - `paid_late`: success order with fine > 0
  - `unpaid`: not paid, 0 days late
  - `fine_window`: not paid, 1–20 days late, or unblocked
  - `blocked`
- `admin_stats(p_term_id)` returns `jsonb`: `registered, paid, paid_on_time, paid_late, unpaid, in_fine_window, blocked, collected_base, collected_fine, collected_total`, plus `per_day: [{day, count, amount}]`. `unpaid` means every not-paid status.
- `admin_students` filter values: `all | paid | unpaid | paid_late | fine_window | blocked`. `unpaid` means every not-paid status. It searches name, phone, email and uuid text with ilike. Rows carry `total_count`.
- `admin_payments` returns orders joined to students, success only unless `p_include_failed`.
- `admin_save_term`:
  - a null `p_id` inserts a new term
  - otherwise it updates, but only the active term (max id); any other id raises `NOT_ACTIVE_TERM`
  - validates amount > 0
- `admin_outbox()` deletes expired rows, then returns the live ones.
- `scripts/create-admin.mjs --url --service-key --email --password` creates or finds the user, inserts into `admins`, and deletes any `students` row.

  - `test_student_forbidden_on_admin_rpcs`: every `admin_*` RPC raises `FORBIDDEN`

  - `test_stats_counts`: 3 students on a term due − 5; one paid on time before the due date was moved, one paid late, one unpaid. Expect paid 2, paid_late 1, unpaid 1, `collected_fine` equal to the late fine.
  - `test_filters_and_search`

### Task 9: 1,000-user load test
